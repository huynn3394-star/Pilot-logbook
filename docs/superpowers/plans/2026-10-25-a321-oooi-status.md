# A321 AOC OOOI STATUS support

Goal: within the existing A320/A321 scanner, accept the second A321 screen layout (OUT/OFF above IN/ON, compact Z clocks), retain FLT LOG support and the target-bound review/save/FINAL guards.
Baseline production commit: 929152a101405f8d2093faacb068b8a6d98a9f38.

Scope: a320-scan.js label-bound parsing, scan-screen.js advisory night-image crop fallback if the existing detector fails, tests, and service-worker cache version only. No airline API, new OCR library, cloud/schema/Firebase or user-record change. Existing importer calls the updated helpers. The user's photo stays local and is never committed or uploaded to public CI; hosted tests use synthetic text/pixels.

Date/UTC/RETURN are not flight event timestamps. The entered OUT UTC date is authoritative for date normalization; screen DATE is not assumed to be OUT date. BLOCK and FLIGHT are independent cross-checks, never replacements. Incomplete or ambiguous columns must remain missing with a warning. A recognized STATUS header permits the constrained final 2/Z clock OCR repair only on immediate event-value rows, with an explicit warning and confidence penalty. Arbitrary five-digit inline numbers are rejected. Scan always creates a review draft, never FINAL automatically.
