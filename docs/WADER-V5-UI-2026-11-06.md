# AviLog interface — Wader 5.0 reference

## Scope and references

The user's target is the **Wader 5.0 app** shown at https://www.waderaviation.com/ and in its [5.0 release post](https://www.waderaviation.com/post/wader-5-0-pilot-logbook-app), not a copy of its marketing homepage. Public reference images were inspected before implementation:

- `hero-devices-v5.29kjq2y16bnjv.webp`: phone logbook hierarchy, floating bottom navigation and tablet rail.
- `briefing-v5.36m_xntycsp6_.webp` and the release overview: map, dark weather/flight cards, larger-screen composition.
- `form-tour.0fmjnv21p3y0e.webp`: grouped flight identity, two-column UTC times and crew.
- Official dashboard image `6902c4_2149f7ba9304409dbb7f90ecf433f747~mv2.png`: pilot identity, totals, map and fleet.

Wader screenshots, logos and product assets are not shipped in Avilog. Avilog retains its name, actual account controls, own icons and its own supported functionality.

## Implemented

- Unified charcoal/navy surfaces, teal accents, translucent navigation, tighter card radii, spacing and native typography; dark/light modes.
- Phone logbook with a compact search/filter row, month headers, UTC flight cards, meaningful FINAL/DRAFT/PLAN states, and an accessible per-flight camera action.
- Floating phone navigation and add button; vertical tablet rail. Existing destinations remain reachable through More.
- Tablet logbook list plus a saved-flight detail pane; larger-screen editor positioned beside the list. The detail pane initially summarizes the latest displayed record; opening any card uses the existing guarded editor.
- Grouped flight form with Log/Airports/Tools, separate dates for every UTC time, compact day/night counters and working save/dirty-form protection.
- Briefing route overview and flight summary with the existing METAR/TAF and editing actions. The original calendar remains available under its own expandable section.
- Dashboard pilot identity, confirmed actual totals, twelve-month bars, recorded PIC/SIC/Night, route map and fleet. Detailed existing statistics remain under an expandable section.
- Weather, crew, account/preferences and study-library surfaces share the palette. Existing weather source validation, stale labels, highlighting and cache v2 remain in place.
- New PWA shell version with the complete local module graph, map data and offline map asset.

No flight schema, cloud transport, authentication, OCR parser, confirmation rules, quiz scoring or persistence implementation was changed by this interface work. The sole editor behavior adjustment is displaying `—` for an empty optional counter without changing its value.

## Map data

The schematic route map uses saved dep/dest airport pairs, **not** live aircraft positions or an actual flown track. Unknown coordinates are explicitly omitted and counted; no route is invented.

- [Natural Earth 110m land](https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_110m_land.geojson), converted to an equirectangular SVG; public domain.
- [OurAirports open data](https://ourairports.com/data/), snapshot downloaded 2026-11-06; 4,983 large/medium airports with four-letter ICAO codes, stored locally as coordinates/IATA/name; public domain.

The public map-data snapshot is display data, not an aeronautical navigation database. Airport mapping contains no personal data. Routes and totals are generated entirely in the browser.

## Verification and fidelity limits

Run `npm run test:wader-ui` for the native Chromium/WebKit browser checks. The harness uses synthetic local guest records and tests 320, 390, 820 and 1180 px, search, filter data preservation, editor tab/draft preservation, save/reload with unchanged original timestamp precision, navigation, overflow and map expansion. At 390px it also creates a flight crossing midnight UTC and operates the takeoff counter. Chromium additionally verifies API failure and cold offline reopening; light-mode captures are taken at 390/1180 px. This does not certify physical iPhone/iPad behavior or live cloud accounts.

- `node scripts/build-atpl-account.mjs`: passed.
- `node --test tests/*.test.js`: 315/315 passed.
- `node scripts/verify-weather-cache.cjs`: Chromium/WebKit passed, preserving the VVPC saved-weather fix and native IndexedDB/worker upgrade behavior.
- `git diff --check`: passed.

Browser captures and machine-readable results are in `test-results/wader-v5/`; that directory is ignored runtime output.

The public references include perspective device mockups and selected screens, rather than an exact screen-by-screen design file. **A 100% pixel-match across the entire Wader app has not been established.** Private/unseen screens and unsupported Wader services (social feed/messages, ADS-B tracking, NOTAMs, wallet and regulatory recency) are not fabricated. The map is schematic and does not reproduce Google's basemap.

This is a source/UI change on its own branch. No merge or Railway deployment is performed as part of the visual review. A local preview is provided for inspection.
